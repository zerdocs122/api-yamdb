# API_YAMDB

**Используемыей технологический стек:**

Python 3.12, Django 5.2, DRF (Django REST framework), API, JWT, pytest

## Описание проекта.
Проект YAMDB содержит списки произведений различных жанров («Сказка», «Рок» или «Артхаус»). Все произведения могут быть отсортированы по категориям («Книги», «Фильмы», «Музыка»).

Основной смысл проекта - сбор отзывов пользователей на конкретные произведения с выставлением рейтинка каждому от 1 до 10. К каждому отзыву возможно оставлять комментарии.

Оставлять отзывы и комментарии могут только зарегистрированные в проекте пользователи.

## Основные пути для запросов:
* Ресурс **auth**: самостоятельная аутентификация пользователей.
* Ресурс **users**: управление пользователями для администраторов проекта.
* Ресурс **users/me**: доступ пользователся к данным своего профиля.
* Ресурс **titles**: произведения, к которым пишут отзывы (определённый фильм, книга или песня).
* Ресурс **categories**: категории (типы) произведений («Фильмы», «Книги», «Музыка»). Одно произведение может быть привязано только к одной категории.
* Ресурс **genres**: жанры произведений. Одно произведение может быть привязано к нескольким жанрам.
* Ресурс **reviews**: отзывы на произведения.
* Ресурс **comments**: комментарии к отзывам.

## Пользовательские роли и права доступа:
* **Анонимный пользователь** — может просматривать описания произведений, читать отзывы и комментарии.
* **Зарегистрированный пользователь (user)** — может читать всё, как и Аноним, может публиковать отзывы и ставить оценки произведениям (фильмам/книгам/песням), может комментировать отзывы; может редактировать и удалять свои отзывы и комментарии, редактировать свои оценки произведений. Эта роль присваивается по умолчанию каждому новому пользователю.
* **Модератор (moderator)** — те же права, что и у Аутентифицированного пользователя, плюс право удалять и редактировать любые отзывы и комментарии.
* **Администратор (admin)** — полные права на управление всем контентом проекта. Может создавать и удалять произведения, категории и жанры. Может назначать роли пользователям.
* **Суперпользователь Django** всегда обладает правами администратора, техническая возможность управления проектом.

## Установка. 
### Запуск проекта на локальной машине.


Клонировать репозиторий и перейти в него в командной строке:

```
git clone https://github.com/dankut25/api-yamdb.git
```

```
cd api-yamdb
```

Cоздать и активировать виртуальное окружение:

```
python -m venv venv
```

```
source venv/Scripts/activate
```

Обновить установщик pip:

```
python -m pip install --upgrade pip
```

Установить зависимости из файла requirements.txt:

```
pip install -r requirements.txt
```

Перейти в папку проекта и выполнить миграции:

```
cd api-yamdb
```

```
python manage.py migrate
```

Запустить проект:

```
python manage.py runserver
```

### Доступ к проекту и Админ-панели находятся по адресу:

```
http://127.0.0.1:8000
```
```
http://127.0.0.1:8000/admin
```


## Примеры запросов:

### Самостоятельная регистрация новых пользователей.

1. Пользователь отправляет POST-запрос с параметрами `email` и `username` на эндпоинт `/api/v1/auth/signup/`.
2. Сервис YaMDB отправляет письмо с кодом подтверждения (confirmation_code) на указанный адрес `email`.
3. Пользователь отправляет POST-запрос с параметрами `username` и `confirmation_code` на эндпоинт `/api/v1/auth/token/`, в ответе на запрос ему приходит token (JWT-токен).
4. В результате пользователь получает токен и может работать с API проекта, отправляя этот токен с каждым запросом. 
4. После регистрации и получения токена пользователь может отправить PATCH-запрос на эндпоинт `/api/v1/users/me/` и заполнить поля в своём профайле (описание полей — в документации).

#### Пример запроса:

```
GET http://127.0.0.1:8000/api/v1/auth/signup/
```

полезные данные

```
{
    "username": "Имя пользователя",
    "email": "Электронная почта, на которую придет код подтверждения"
}
```

### Заполнение полей в своём профайле пользователя после регистрации и получения JWT-токена.

#### Пример запроса:

```
PATCH http://127.0.0.1:8000/api/v1/users/me/
```

полезные данные

```
{
    "username": "Имя пользователя"
    "email": "Электронная почта, на которую придет код подтверждения"
    "first_name": "Имя",
    "last_name": "Фамилия",
    "bio": "О себе"
}
```

### Создание записи о произведении.

#### Пример запроса:

```
POST http://127.0.0.1:8000/api/v1/titles/
```

полезные данные

```
{
"name": "Название произведения",
"year": 2000 - целое число меньше или равное текущему году,
"description": "Описание произведения",
"genre": [
"Короткое имя на латинице, например, drama",
"comedy"
],
"category": "Короткое имя на латинице, например, film"
}
```

Получить список всех произведения может любой желающий, отправив запрос:

```
GET http://127.0.0.1:8000/api/v1/titles/
```

```
json
{
    "id": 1,
    "name": "Название произведения", 
    "year": 2000,
    "rating": 8,
    "description": "Описание произведения",
    "genre": [
        {
            "name": "Драма",
            "slug": "drama"
        },
        {
            "name": "Комедия", 
            "slug": "comedy"
        }
    ],
    "category": {
        "name": "Фильмы",
        "slug": "films"
    }
}
```

Поле rating содержит средний рейтинг произведения (целое число)
Если отзывов нет, rating будет null

### Создание отзыва о произведении.

Зарегистрированные пользователи могут оставлять отзывы на произведения. На одно произведение можно оставить только один отзыв.

#### Пример запроса:

```
POST http://127.0.0.1:8000/api/v1/titles/{title_id}/reviews/
```

Полезные данные:

```
json
{
    "text": "Текст отзыва",
    "score": 8
}

```

Один пользователь = один отзыв на произведение
score (обязательный) - оценка от 1 до 10

### Создание комментария к отзыву.

Зарегистрированные пользователи могут оставлять комментарии к существующим отзывам.

#### Пример запроса:

```
POST http://127.0.0.1:8000/api/v1/titles/{title_id}/reviews/{review_id}/comments/
```

Полезные данные:

```
json
{
    "text": "Текст комментария"
}
```

Можно комментировать любые отзывы, не только свои

### Тестовые данные:

#### Протестировать проект можно, установив тестовые данные.

Команда load_data аботает через Django management command и импортаирует данные в модели приложения.
Она предназначена для первоначальной загрузки данных в базу данных из CSV файлов. Поддерживает как полную загрузку всех данных, так и выборочную загрузку определенных моделей.

#### Поддерживаемые модели:

Команда поддерживает загрузку данных для следующих моделей:

* **category** - Категории произведений
* **genre** - Жанры произведений
* **title** - Произведения (книги, фильмы и т.д.)
* **genretitles** - Связи произведений с жанрами
* **user** - Пользователи системы
* **review** - Отзывы на произведения
* **comment** - Комментарии к отзывам

#### Требования:

1. CSV файлы должны находиться в директории static/data/
2. Файлы должны иметь определенные имена (указаны в конфигурации)
3. CSV файлы должны содержать обязательные поля для каждой модели

####  Структура CSV файлов:

* Кодировка: UTF-8
* Разделитель: запятая
* Первая строка должна содержать заголовки столбцов

  
####  Конфигурация:

Настройки моделей и их CSV файлов находятся в словаре MODEL_CONFIG внутри класса команды. При необходимости можно добавить новые модели или изменить существующие настройки.

####  Использование.

Базовая команда (загрузка всех данных):

```
bash
python manage.py load_data
```

Выборочная загрузка определенных моделей, например, только категорий и жанров:

```
bash
python manage.py load_data --models category genre
```
